# اتصال حساب واقعی بوروس و بررسی SDK — ۳ اکتبر ۲۰۲۶

## نتیجه

دارینو اکنون مسیر فقط‌خواندنی حساب بوروس و پیش‌نمایش رسمی ورود دارد. SDK کامل نصب نشده است: REST API تمام داده‌های موردنیاز این مرحله را می‌دهد، و واردکردن وابستگی‌های معامله و امضا سود مشخصی برای این اتصال ندارد. هیچ Agent، کلید خصوصی کیف پول، امضا، تولید calldata یا ارسال تراکنش اضافه نشده است.

## بررسی بسته بدون اجرای آن

- بسته رسمی npm: `@pendle/boros-sdk-public@0.4.0`، مخزن معرفی‌شده `pendle-finance/boros-sdk-public`.
- فایل tarball بدون نصب دانلود شد؛ محتوای فایل‌های عادی به مسیر موقت جدا استخراج شد؛ لینک‌ها و مسیرهای traversal استخراج نشدند.
- SHA-512 فایل با `dist.integrity` رجیستری npm تطبیق داشت. این تطبیق، صحت دانلود نسبت به رجیستری است، نه اثبات نبود بدافزار یا تأیید مستقل امضای ناشر.
- جست‌وجوی ایستا در خروجی JavaScript منتشرشده نشانه‌ای از `child_process`، اجرای shell، خواندن فایل شخصی، Chrome profile، Keychain، `.ssh`، `eval` یا `new Function` پیدا نکرد. `node:crypto` برای امضا و یک متغیر محیطی تنظیم multicall وجود دارد؛ خود SDK قابلیت‌های شبکه و معامله دارد.
- manifest SDK اسکریپت `prepare: husky install` دارد. اسکریپت‌های build/prepack نیز موجودند؛ هیچ‌کدام اجرا نشدند.
- وابستگی‌ها: viem 2.55.10، axios، date-fns، lru-cache، `@pendle/boros-core` و `@pendle/boros-offchain-math@1.0.6`. manifest دو بسته Pendle بررسی شد؛ core وابستگی‌هایی از LayerZero و OpenZeppelin هم دارد. کل درخت وابستگی‌ها و زنجیره تأمین به‌صورت کامل ممیزی نشده است.
- نصب بسته Node با مجوزهای کاربر می‌تواند در صورت وجود کد مخرب به فایل‌های قابل‌خواندن همان کاربر دسترسی پیدا کند؛ مجوز خواندن فایل با امکان رمزگشایی همه اسرار مرورگر یکسان نیست. صرف نام SDK یا تطبیق هش، ضمانت امنیت نیست.
- نتیجه اجرایی: SDK نصب/اجرا نشد و package.json/package-lock.json تغییر نکرد. تبدیل شناسه حساب از چیدمان رسمی بیت‌ها و تبدیل x18 با BigInt پیاده و آزموده شد؛ Decimal موجود فقط برای نمایش مقدار خام استفاده می‌شود.

## پیاده‌سازی

- `/api/borosAccount`: نشست معتبر دارینو، CSRF موجود برای POST، no-store خصوصی، دامنه بالادست ثابت، ورودی محدود و DTO سخت‌گیرانه. تنها GET حساب و POST شبیه‌سازی مجاز است؛ payload امضا و پارامترهای اضافی رد می‌شود.
- اصلاح ۳ اکتبر: خواندن عمومی موجودی و بازار به `BOROS_API_KEY` نیاز ندارد و هیچ Bearer ارسال نمی‌شود. توضیح قبلی دربارهٔ کلید REST اشتباه بود. کلید امضای Ed25519 و `x-pendle-auth` مربوط به مسیرهای حفاظت‌شده‌اند؛ دارینو از آن مسیرها استفاده نمی‌کند.
- پروکسی بازار تنها مسیرهای عمومی مجاز را می‌خواند. endpoint اختصاصی حساب دارینو همچنان نشست معتبر می‌خواهد؛ کلید یا قابلیت معامله اضافه نشده است.
- حساب اصلی از `market-acc-infos-by-root` خوانده می‌شود؛ این endpoint فقط accountId صفر را کشف می‌کند. حساب‌های ۱–۲۵۵ با انتخاب صریح شماره حساب پشتیبانی می‌شوند؛ cross وثیقه‌ها و isolated پوزیشن‌های فعال کشف می‌شوند. isolated بدون پوزیشن در حساب فرعی ممکن است کشف نشود و به‌صراحت partial است.
- API زنده حساب: active-positions، market-acc-infos، settlement-events، transfer-logs، orders. اصل مالکیت root/accountId، جهت signedSize و یکتایی حساب/پوزیشن کنترل می‌شود.
- کش حافظه سرور حساب ۴۵ ثانیه با dedup؛ پیش‌نمایش یکسان ۱۰ ثانیه با dedup. کلاینت به‌طور معمول هر ۶۰ ثانیه هنگام مشاهده تازه می‌کند و پس از 429 حداقل ۶۰ ثانیه توقف می‌کند.
- آخرین snapshot معتبر و انتخاب حساب در IndexedDB این دستگاه حفظ می‌شود؛ خرابی یا سهمیه، آن را با صفر جایگزین نمی‌کند. وضعیت همگام‌سازی واقعی backend در freshness لحاظ می‌شود. حذف اتصال و خروج، داده این بخش را پاک می‌کند؛ پاسخ دیررس پس از خروج اعمال نمی‌شود.

## نمایش و محاسبات

- تب «حساب من»: اکویتی، وثیقه، مارجین آزاد/لازم، بافر نگهداری، پوزیشن لانگ/شورت فاندینگ، نرخ ورود، نرخ لیکوییدشدن دریافتی، سود تحقق‌نیافته، سود معاملات و تسویه از ابتدای همان بازار، سفارش باز و رویدادهای اخیر.
- لوگوهای محلی سیستم طراحی، نام فارسی، ارقام فارسی و مقدار پیش از واحد؛ شبکه آربیتروم در گوشه پایین لوگوی وثیقه. معادل تومان از همان نرخ تتر اپ استفاده می‌کند؛ نبود نرخ، عدد ساختگی نمی‌سازد.
- تمام موجودی‌ها/پوزیشن‌ها/تسویه‌ها در API حساب x18 هستند؛ حتی وثیقه تتر با decimals native شش. مقدار سفارش از متن اعشاری به BigInt تبدیل می‌شود و تا ۱۸ رقم اعشار حفظ می‌شود.
- سود معامله خالص گزارش‌شده با سود تسویه جدا است. هزینه تسویه در settlement خالص کسر شده؛ دوباره کسر نمی‌شود. جریان‌های داخلی و واریز/برداشت سود حساب محسوب نمی‌شوند.
- دلار فعلی = مقدار وثیقه × قیمت فعلی همان وثیقه. این «معادل فعلی» است، نه سود دلاری تاریخی. مجموع PnL فعال، سود تمام حساب شامل بازارهای بسته‌شده نیست.
- «تسویه باقی‌مانده با فرض نرخ جاری» فقط در داده تازه حساب/بازار محاسبه می‌شود: جهت × اندازه YU × (floating APR − fixed APR) × سال باقی‌مانده × قیمت وثیقه. این برآورد قبل از هزینه است و با سود تحقق‌یافته/ارزش خروج امروز جمع نمی‌شود.
- ارزش حساب بوروس فعلاً جدا از مجموع داشبورد است. برای افزودن به مجموع باید تطبیق پوشش Zerion و منابع حساب با شناسه معتبر انجام شود؛ نماد به‌تنهایی کافی نیست. جمع خودکار می‌تواند دارایی را دوبار بشمارد.

## پیش‌نمایش رسمی و سناریو

- endpoint زنده `POST /apis/v1/simulations/place-order` با FOK، جهت، اندازه x18، marketAcc و حد لغزش نرخ؛ بدون امضا و سفارش واقعی.
- نمایش حجم تطبیق، میانگین نرخ تطبیق، مارجین کل حساب پس از سفارش و liquidation APR. موفقیت فقط برای statusCode Succeed + FILLED + تطبیق کامل اندازه است؛ FOK بدون تطبیق به‌عنوان ورود موفق نمایش داده نمی‌شود.
- matched.cost مبلغ تطبیق است؛ آن را کارمزد فرض نمی‌کنیم. پاسخ فعلی به‌تنهایی هزینه کامل یا گس را نمی‌دهد.
- دکمه «استفاده از حجم و نرخ در سناریو» اندازه و نرخ تطبیق را به تحلیل دستی منتقل می‌کند؛ لغزش در نرخ لحاظ شده و دوباره به هزینه افزوده نمی‌شود. نرخ پذیرفته‌شده بعد از سه دقیقه یا تغییر بازار/جهت/اندازه معتبر نیست. سرمایه دستی و مارجین برآورد یک پوزیشن با مارجین کل حساب پس از شبیه‌سازی یکی نیستند.

## دستیار

- آماده‌سازی داده دستیار، حساب انتخابی را نیز تازه می‌کند؛ آدرس، marketAcc، شناسه رویداد و کلید API ارسال نمی‌شود.
- خلاصه اکویتی و مارجین، داده پوزیشن واقعی، جریان‌های تسویه و انتقال، سفارش‌ها، سناریوی دستی و پیش‌نمایش رسمی وارد context بخش بوروس می‌شوند.
- وضعیت، زمان، منبع، پوشش ناقص و محدودیت‌ها همراه داده‌اند. داده حساب واقعی در ابتدای بخش قرار دارد تا قبل از بازارهای عمومی به‌دلیل سقف تعداد حذف نشود.
- دستیار حق معامله/امضا ندارد. سود واقعی، برآورد آینده، سناریوی دستی، پیش‌نمایش رسمی و داده عمومی جدا هستند. اطلاعات قدیمی یا نامعلوم تضمین سود ایجاد نمی‌کند.

## اعتبارسنجی

- کل مجموعه: **۱۱۶۵ تست در ۹۹ فایل** موفق.
- TypeScript کلاینت و سرور و build وب/PWA موفق؛ ۱۳۶ فایل precache.
- مرورگر با حساب/پاسخ‌های ساختگی: اتصال حساب، حفظ موجودی پس از 429، ارسال دقیق ۰.۶۵ به x18، مارجین وثیقه به دلار، عرض ۳۲۰/۳۹۰/۱۴۴۰ و روشن/تیره و touch بدون بیرون‌زدگی.
- پنج تب و سناریوهای قبلی بوروس نیز آزمون مرورگر را گذراندند.
- پاسخ عمومی `/assets?isCollateral=true` واقعاً دریافت و ساختار آن با mapper تطبیق شد. حساب شخصی کاربر، کلید واقعی، پوزیشن واقعی و پاسخ زنده Gemini آزمایش نشده‌اند. نصب PWA روی دستگاه واقعی آزمایش نشده است.
- تغییرات آماده بازبینی‌اند؛ merge و deployment انجام نشده است. شاخه شامل تغییرات قبلی ممیزی بوروس، تحلیل ورود و context دستیار نیز هست.
